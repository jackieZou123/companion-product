# 玫莉蔻岗位要求（决策用）

做任何功能前先对照这份 JD。完整原文见 [reference.md](reference.md)。

## 我们在做什么

面向成年用户的中文 AI 陪伴。文本是主链路。语音 / 视频 / Avatar 只旁路，不拖垮对话。

真正关心：听完整、听得懂、像同一个人、说得自然、记得准确且可控，需要时能合理拒绝；工作里能帮上忙（预约、进度），但不靠编造业务数据。

现有模型供应商是可复现基线，不是永久绑定。

## 什么叫好的陪伴（验收）

| 标准 | 含义 |
| --- | --- |
| 角色一致 | 长对话不改身份、价值观、关系、语言风格 |
| 主动而不打扰 | 有触发、频控、TTL，不是模型突然想说话 |
| 有情绪与共情 | 内容/语气/节奏一致，不是安慰套话 |
| 有边界 | 不无脑赞同、不诱导依赖，拒绝要自然且一致 |
| 丰富但不失控 | 降重复，模式可多，事实和人设不能破 |
| 记忆可控 | 短期 / 画像 / 事件 / 关系分开；可纠正、可删除、可隔离 |
| 实质帮忙 | 预约、进度等能办成事；人话由角色说，数字由业务接口负责 |

## 发布顺序

1. **P0** 可靠性：流式、失败恢复、延迟、会话持久化、安全门
2. **P1** 长期记忆与关系连续性；主动消息
3. **P2** 实时多模态 / Avatar 旁路；评测集做硬

不为了功能数量牺牲长期陪伴质量。不把所有问题塞进一个 Prompt 或一次模型调用。

## 工程底线

- 供应商走适配层；上新方案必须和基线对照（体验、P95、稳定、成本、隐私、回退）
- 主观体验要变成固定样本、指标、失败样本（LangSmith）
- 密钥、日志、监控、会话隔离、重试、可复现部署
- 安全写进产品：AI 标识、成人边界、审核、反依赖、极端情绪、数据最小化与删除

## 不要做

- 把角色改成智能客服 / FAQ / 工单；排班库存不要塞进人设（见 `companion-actions`）
- 只接 API、Happy Path、套壳 UI
- 无限迎合用户
- 视觉层当成对话智能
- 禁止AI自己意象起名字。角色名、呼唤词只用用户给定或已有资料；没有就问，不要编花名

改架构或加节点时：先问「这是角色体验、完整链路，还是工程结果？」三件事对不上 JD 的，默认不做。
