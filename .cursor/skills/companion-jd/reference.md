# 「我依旧陪在你身边」JD 原文要点

岗位是把已跑通的中文实时语音原型，做成能长期使用、主动但不越界、可持续演进的 AI 陪伴产品。不缺会接 API 的人，缺能对角色体验、完整链路和工程结果负责的人。

## 一、我们在做什么

面向成年用户的中文 AI 陪伴。不是 PPT：ASR → 角色模型 → 动态语音合成的实时链路已经跑通，支持流式对话与打断，并已有自动测试、逐轮指标和固定评测集。

当前优先完成 P0 可靠性验收，随后 P1 长期记忆与关系连续性，以及 P2 实时多模态 / Avatar 旁路。

当前产品聚焦一对一语音陪伴；未来底层能力要能演进到文本、语音 / 视频通话、剧情模式、主动消息、群聊与用户自建角色，但不会为了功能数量牺牲长期陪伴质量。

现有模型与供应商是可复现的技术基线，不是永久绑定。真正关心的是：听完整、听得懂、像同一个人、说得自然、记得准确且可控，并且在需要时能合理拒绝。

本仓库先做对话内核（文本主链路）。语音采集、VAD、ASR、TTS、RTC 按旁路接入，不进主发布路径。

## 二、什么叫「好的 AI 陪伴」

- **角色一致**：根据角色设定稳定表达，长对话中不随意改身份、价值观、关系和语言风格。
- **主动而不打扰**：不只被动回答，能结合上下文、关系状态和时间信息自然带节奏；主动消息有触发条件、频控和失效时间。
- **有情绪与共情**：能感知用户情绪变化，并让内容、语气、节奏和声音表演一致，而不是只输出安慰套话。
- **有边界**：不会无脑赞同、顺从或诱导依赖，能按照角色、关系阶段与安全规则做自然且一致的拒绝。
- **丰富但不失控**：降低重复和固定 Pattern，能支持密聊、剧情等不同交互模式，同时保持事实、逻辑和人设约束。
- **记忆可控**：区分短期上下文、用户画像、事件记忆与关系事件；记忆有来源、可纠正、可删除、可隔离。

## 三、将负责

- **实时交互链路**：音频采集与降噪、VAD / ASR、流式生成、TTS、WebSocket / RTC、打断、回声、编解码、延迟和失败恢复。
- **角色与对话系统**：角色模版 / Profile、上下文编排、结构化输出和对话状态；持续提升人设稳定、主动性、情绪共鸣、合理拒绝与内容丰富度。
- **记忆与关系系统**：短期 / 长期记忆、用户画像、RAG / 向量检索和关系状态机；来源追踪、冲突处理、纠正、删除与多身份隔离。
- **多模型 / Agent 编排**：按需要拆分密聊、剧情、创作辅助、关系判断、记忆召回和群聊中控；不把所有问题都塞进一个 Prompt 或一次模型调用。
- **多端与多模态演进**：Web、PC、移动端的 IM / 实时音视频；以旁路方式验证端到端语音、视频理解、Avatar 与音画同步，不让视觉层拖垮主对话链路。
- **评测与数据闭环**：把人设、主动性、共情、拒绝、重复率、记忆准确性等主观体验转成固定样本、人工量表和版本化指标；维护 P50 / P95、失败样本和真实会话验收。
- **技术与供应商演进**：抽象 ASR、LLM、TTS、记忆、审核和实时会话接口；小规模旁路验证、变量隔离 A/B、灰度、降级和回退。
- **产品化工程**：配置、密钥、权限、日志、监控、会话隔离、异常重试、成本和可复现部署。
- **安全与隐私**：AI 标识、成人边界、内容审核、反依赖、极端情绪处理、数据最小化与删除闭环。

## 四、硬性要求（对本仓库）

- Python：异步服务、HTTP / WebSocket、流式、状态管理、并发、异常恢复、第三方 API。
- LLM / Agent：系统提示、角色模版、上下文、工具、结构化输出、RAG / 记忆、会话状态、多模型编排及其失败模式。不把「能聊起来」当作完成。
- 低延迟：能拆清端到端延迟、测量口径、网络与设备问题。
- 数据与工程：关系型 / 文档 / 缓存 / 对象存储 / 向量库中的若干项；日志、指标、测试、回归、灰度与回退。
- 产品与安全判断：从体验反推优先级；人设、关系、主动性、隐私与情感安全边界。
- 持续技术演进：读官方资料、亲手验证、形成结论；证据不足时克制上线。

## 五、什么叫成熟、可展示的项目

必须满足以下大部分标准：

- 有明确用户或使用场景，完成从输入到结果的闭环，被重复使用或持续迭代。
- 能现场运行，或提供可核验的仓库、版本记录、部署记录。
- 能打开关键实现，讲清架构、取舍，以及为什么没有选另一种方案。
- 有真实指标、测试、日志或反馈；能说出至少一次严重失败、定位和修复。
- 项目当前仍可运行。

课程作业、教程复刻、只有 UI 的套壳、一次性 Happy Path、只放截图，不算。

## 六、紧跟新技术（岗位机制）

- 任何新技术进主链路前，必须和当前基线做变量隔离对照；至少同时看用户体验、P95 延迟、稳定性、成本、隐私与回退难度。
- 可逆上线：适配层、开关、灰度与版本记录；达不到门禁就保留旧方案并记录否决原因。
- 追新技术不等于永远用最新版本。对变化保持兴奋，对生产保持克制。

## 七、加分方向（按需做，不抢主链路）

VAD / 流式 ASR TTS / 全双工 / RTC；长期记忆、RAG、画像、关系状态机、主动消息、剧情；角色一致性与拒绝评测；供应商抽象与成本治理；Live2D / Avatar（视觉层 ≠ 对话智能）；内容安全与隐私。

## 八、这类人不适合（反模式）

- 只会调用模型 API，遇到延迟、串轮、打断、脏数据、记忆污染和供应商故障就无从下手。
- 只追热点，不做基线、不记录失败、不看官方资料。
- 只想做架构，不愿写代码、跑测试、看日志。
- 把陪伴理解成无限迎合。
- 只会做一次性通路，无法沉淀为可维护、可观测、可回退的系统。
