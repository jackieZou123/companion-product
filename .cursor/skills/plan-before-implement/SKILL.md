# 先方案后实施（Plan 门禁）

## 铁律（用户要求，verbatim）

**必须要先出方案，先 plan，再执行；用户说确认才能开始。**

Agent **不得**在未经用户明确确认的情况下，直接改安全门、角色 Profile、对话图主路径，或流式与非流式分叉。

---

## 何时强制本 Skill

| 场景 | 示例 |
|------|------|
| 安全门 | `SafetyPolicy`、refuse code、出口审核 |
| 角色人设 | `character/profiles/*.json`、默认角色、呼唤池 |
| 对话图 | `dialogue/graph.py` 增删节点、改边、跳过 safety |
| 流式分叉 | `stream_turn` 与图不同步 |
| 用户明确要求 | 「先定方案」「不要直接改」「出 plan」 |

**可跳过 Plan（仍建议简短说明）**：纯文案、typo、评测样本补一句、用户已贴完整方案并说「按这个做」。

---

## 标准流程（必须按序）

调研 → 出方案 → 等待用户确认 → 实施与 `pytest`。

### 1. 调研

- 读相关 Skill、`companion-jd`、现有图与测试
- 弄清根因与**不改动的边界**
- **禁止**在此阶段写实现代码或「顺手修一下」

### 2. 出方案

- 背景与根因
- 改哪些文件、不改哪些
- 节点/边（必要时 mermaid）
- 评测与测试怎么补
- **禁止**边写方案边改仓库

### 3. 等待确认

仅当用户明确表示「确认」「可以做了」「按方案执行」「Implement the plan」或批准 Plan 后，才可进入实施。

### 4. 实施

- 严格按已确认方案的范围改，不擅自扩大
- 改完 `pyrefly check src tests` 与 `pytest`（见 `verify-service`）
- 有偏差须在回复中说明

---

## 禁止

- 用户报 bug 后**直接改**安全门 / 人设 / 图而不先出 Plan（除非用户明确说「直接修」）
- 用「小改动」绕过确认去动 `graph.py` 或 `SafetyPolicy`
- 把 T7 设备 Skill 的流程当成本仓实现蓝图
